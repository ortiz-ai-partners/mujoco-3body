## 本文（6 ページ以内）

### 表紙（1/3 ページ）

- 題：「アイランドマスター — 3 体のロボットが協力して峠を越える：失敗したときの次の一手を選ぶ支配人 AI と、気持ちを推論する気分ネット」
- 動画 URL（YouTube）、GitHub URL（`mujoco-3body`。土台の `physical-ai-course-builder` は README からリンク）。
- 注記 3 行：「動画は 0:00〜2:26 が 2 倍速、2:26〜2:44 が等速（画面右下に常時表示）」「ツール：MuJoCo 3.11。自作の course-builder（ブルドーザーの施工・走行）を土台に、Pollen Robotics の Microduck と KingKong Robotics の Jumper の公式バンドルを統合」「AI の活用：推論（公式ポリシー 4 本・支配人 AI・気分ネット）と学習（支配人 AI、気分ネット）」。

### 1. 概要（2/3 ページ）— 図⑦

- 動画の筋を 5 行：BZ が坂を運んで峠を作る → BZ が渡る → パッカンが 16° の坂に 2 回挑んで座り込む → 跳跳が横から越える → 支配人 AI が 5 手を選び、跳跳がパッカンを押し上げて 3 体とも渡り切る → 輪になって万歳。
- 本番で 2 つの AI が推論している：支配人 AI（次の一手）と気分ネット（跳跳の表情）。
- 結果を 1 行：同じ 30 シードの評価で固定ルール 29／PPO 26／Q 表 25／ランダム 14（30 話中）。
- 小さな表「加点要素とこの資料の対応」：創造性 → §2・§5.1〜5.2、技術力 → §4・§5.3〜5.5、実用性 → §7、表現力 → §8 と動画。

### 2. 目的と課題設定（2/3 ページ）— 図④

- 題材：性質の違う 3 体（ブルドーザー＝自作の course-builder、パッカン＝Microduck、跳跳＝Jumper）を 1 つの MuJoCo 空間に集め、「峠を作って全員が渡る」を協力でやる。
- 問い：手持ちの動作（公式ポリシー）が失敗したとき、誰がどう次の一手を決めるか → 支配人 AI。
- 自分たちに課した制約：物理のみ（外力・瞬間移動なし）、公式ポリシーは推論のみ（改造しない）、BZ はパッカンに触れない（安全）、コースを壊さない、描画は物理に影響しない。
- MuJoCo を選んだ理由：2 体の公式ポリシーがどちらも MuJoCo 用で、自作のブルドーザーも MuJoCo。同じ物理の上で推論のまま動かせる。
- 創造性の主張：「失敗する前提の筋書き」と「助ける側（カニ）と判断する側（支配人）を分けた」構図。

### 3. 何が既製で何が自作か（1/3 ページ、表）

- 既製（出典とライセンスを明記）：MuJoCo 3.11（Apache-2.0）、Microduck のモデルと公式 ONNX ポリシー velstand／alpha_sitstand（Pollen Robotics `microduck_rl`、Apache-2.0、3D モデルは同リポジトリの別ライセンス）、Jumper のモデルと公式 ONNX ポリシー locomotion／jump／dance_crab（KingKong Robotics `jumper`、Apache-2.0）、rsplan（Built Robotics、MIT、course-builder に版固定で同梱）、onnxruntime、Stable-Baselines3、PyTorch。
- 自作（この課題のために 2026-10-08 から）：**course-builder**（ブルドーザーのモデル、坂の部材と施工手順、運搬・走行の規則制御、空荷の高速走行。別リポジトリ）、3 体の統合（MjSpec）と筋書き、支配人 AI（観測・6 つの手・学習環境 v2・報酬 v2.2・学習・同一シード評価）、気分ネット（データ収集・学習・しきい値）、表情 11 種と 17 規則と顔モニター、動画の仕組み（省略・倍速表示・鳴き声）、物理不変の検査、評価の道具。
- 公式ポリシーは改造せず推論のみ。跳跳の前方ジャンプは公式 jump の関節目標に股関節ヨーの掃きを重ねたもの（関節目標のみ、外力なし）と明記。

### 4. システム構成（1.5 ページ）— 図①⑤②⑥

- 4.1 舞台：MuJoCo 3.11、MjSpec で 3 体を結合、コース v2（峠の隙間 1 cm）、時間刻み 0.005 → 施工後 0.001。
- 4.2 ロボットと公式ポリシー：パッカン velstand（観測 61）＋sitstand、跳跳 locomotion（観測 415、200 Hz）・jump（167）・dance（209）、BZ は規則制御（NN なし）。
- 4.3 支配人 AI：観測 46 次元、6 つの手（座らせる／押し上げ／離れる／立たせる／見送る／待つ）、3 方式（固定ルール、Q 表、PPO 46-64-64-6）、学習環境 v2（カニが押し上げる）、報酬 v2.2、開始場面 7 種（転倒済みを含む）。
- 4.4 気分ネット：入力 53（観測 46＋手 6＋経過時間 1）→ 32 → 32 → 5（成功・止まる・転ばせる・空振りの確率＋渡れる確率）。学習データは学習環境の 35 話・47,952 サンプル、450 エポック目を検証用の正解率で選択（4 分類 0.80、成功 vs 失敗 0.83）。本番は 0.02 秒ごと約 5,000 回推論。
- 4.5 表情の決め方：気分ネットの確率＋計測値（接触力、押している時間、進み、転倒、傾き）を 17 の規則で 11 の顔に。顔モニターに決め手の値を常時表示。

### 5. 工夫点（1 ページ）

- 5.1 失敗を筋書きの中心に置いた：パッカンが 16° を登れないのは事実。隠さず、支配人が手を選ぶ場面にした。
- 5.2 「座ったパッカンがカニの方を向く」と縁で倒れない、の発見：3/3 を成立させた鍵（押し倒し案は BZ 禁止で封印、後ろから押す案は転倒、向きを変えて解決）。
- 5.3 動作の失敗と判断の失敗を分けて評価：同じシードで固定ルールと学習方式を 2×2 で比べる。
- 5.4 描画は物理に戻らない：顔・モニター・省略を付けても状態のハッシュ（qpos＋qvel の sha256）が一致することを毎回確認。省略の初版で物理が変わったのをこの検査で捕まえて直した。
- 5.5 評価の落とし穴を直した：評価エピソードが独立していなかったバグ、峠の隙間で足が挟まる問題（コース v2）。
- 5.6 見せ方：2 倍速と省略を画面に明記、顔モニターで AI の判断根拠を見せる、3 体それぞれの祝い方。

### 6. 結果（2/3 ページ）— 図③

- 評価 v4（新コース、30 シード、独立エピソード）：渡り切り 固定ルール 29／PPO v2.2 26／Q 表 25／PPO 中規模 23／ランダム 14。固定ルールとの同一シード 2×2、手数と転倒の平均。
- 旧コースでは PPO 16/30 → コース修正で 26/30：環境の不備が学習方式に厳しく出ていた。
- 気分ネットの検証用正解率と、take 46 での推論の様子（押し上げ中の成功確率 0.95〜0.99）。
- 動画 take 46：3/3、支配人 5 手、押し上げ 71 秒（動画 36 秒）、全長 2:44。

### 7. 考察・実用性・反省（2/3 ページ、優秀生選出の観点で手を抜かない）

- 固定ルールが学習方式に勝った理由：場面が小さく、人の知識を規則に書けた。学習の価値が出るのは規則が想定しない場面（転倒済みなど）で、そこは報酬 v2.2 で穴を塞いだ。
- うまくいかなかったこと：PPO の価値関数を気分に使う案（押し上げ中ずっと −22 で却下）、PPO 継続学習の中断、押し倒し案、初期の評価バグ。
- 実用性：「動作は既製、判断は支配人、根拠は顔に出す」の構図は、複数ロボットの現場（搬送・施工）で人が監督する形に向く。限界：シミュレーションのみ、支配人の観測は手設計、コースは固定。
- 反省：計測より先に設計した所（接触力の目盛り）、PPO に使った時間、評価の独立性を最初に確かめなかったこと。

### 8. 動画の構成と再現方法（1/2 ページ）— 図⑦

- 10 区間、省略 2 か所（32 秒・62 秒、物理は走っている）、3 つの渡り切り、支配人の 5 手、2 倍速と等速の区間、跳跳の顔の帯。音は 3 体の鳴き声（合成）。BGM・字幕を付けた場合はここに 1 行。
- 再現：環境（Python 3.10、mujoco 3.11.0、onnxruntime、SB3、PyTorch）、主なコマンド 4〜5 行、`out/` に残した全テイク（失敗したものも）。詳細（17 規則としきい値、表情ログ、評価の 2×2 表、試行の履歴、観測 46 次元の内訳）は GitHub の README・設計メモ・HANDOVER に置き、リンクで示す。
